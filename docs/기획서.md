# Anna Wedding 서비스 기획서

> 웨딩 토탈 디렉팅 웹 서비스 · 학습용 데모 프로젝트

## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| **서비스명** | Anna Wedding (애나웨딩) |
| **한 줄 정의** | 드레스 · 스튜디오촬영 · 메이크업&헤어 세 축을 중심으로, 서울 · 대전 · 충청권 · 부산 · 전주 지역의 예비 신랑신부에게 맞춤 웨딩 준비를 연결 · 디렉팅 · 상담해주는 웨딩 토탈 디렉팅 플랫폼 |
| **타겟 사용자** | 결혼을 6개월~1년 내 앞두고 있고, 웨딩 준비 정보 탐색에 시간을 쓰기 어려운 20대 후반~30대 예비부부 (특히 지방 거주 또는 지역 이동 결혼 준비 커플) |

### 핵심 가치

1. **의사결정 시간 단축** — 예산 · 취향 · 지역을 입력하면 AI가 맞춤 웨딩 패키지(드레스/스튜디오/메이크업 조합)를 추천해 준다.
2. **지역 정보의 통합** — 지역별(서울 / 대전 / 충청권 / 부산 / 전주) 파트너사와 진행 방식 정보를 한 곳에서 확인할 수 있다.
3. **실제 예약으로의 연결** — 전문 디렉터 상담을 통해 실제 예약까지 자연스럽게 이어진다.

### 문제 정의

웨딩 준비 초기 단계의 예비부부는 다음 문제를 겪는다.

- 드레스 · 스튜디오 · 메이크업을 **각각 따로** 알아봐야 해서 탐색 비용이 크다.
- 실제 시세를 모르는 상태에서 **예산을 어떻게 나눠야 할지** 감이 없다.
- 지역마다 진행 방식과 가격대가 달라 **비교 기준을 세우기 어렵다.**

Anna Wedding은 이 세 가지를 하나의 입력 폼과 하나의 결과 화면으로 해결한다.

## 3. AI 기능 설계 — "맞춤 웨딩 패키지 추천"

### 3-1. 입력값

| 입력 항목 | 형식 | 값 |
| --- | --- | --- |
| 예식 지역 | select | 서울 / 대전 / 충청권 / 부산 / 전주 |
| 총예산 | 슬라이더 (만원 단위) | 100 ~ 2,000만원 (서버는 5,000만원까지 허용) |
| 웨딩 스타일 취향 | select | 로맨틱 / 모던 시크 / 클래식 / 내추럴 / 럭셔리 |
| 예식 예정 시기 | month | 예) 2026년 11월 |
| 가장 중요한 항목 | radio (1순위) | 드레스 / 스튜디오촬영 / 메이크업&헤어 |

### 3-2. 출력값

1. **추천 웨딩 패키지 요약** — 드레스 콘셉트 / 스튜디오 촬영 콘셉트 / 메이크업&헤어 스타일 제안
2. **상세 예산 플랜** — 5개 항목의 금액 · 비율 · 한 줄 코멘트 (4장 참고)
3. **진행 팁 및 다음 단계 안내** — 해당 지역·시기 기준 주의점과 상담 신청 유도 문구

결과는 카드 UI로 표시하며, `다시 추천받기` / `이 결과로 상담 신청하기` 버튼을 제공한다.
후자를 누르면 입력값과 추천 결과가 상담 폼의 문의 내용에 자동으로 채워진다.

### 3-3. 사용자 가치

웨딩 준비 초기 단계의 막막함을 줄이고, **자신의 예산 안에서 현실적으로 가능한 방향**을
즉시(약 30초 내) 확인할 수 있다.

### 3-4. 실패 처리

| 실패 유형 | 처리 방식 |
| --- | --- |
| **빈 입력 (필수값 누락)** | 클라이언트에서 먼저 검증해 "예식 지역을 선택해 주세요." 등 구체적 문구를 폼 근처에 표시하고, **API 호출 자체를 차단**한다. 해당 필드에 오류 스타일을 적용한다. |
| **API 오류 (4xx)** | "입력 정보를 다시 확인해 주세요" + 서버가 내려준 사유를 표시한다. |
| **API 오류 (5xx)** | "추천을 불러오는 중 문제가 발생했어요. 잠시 후 다시 시도해 주세요." 카드와 **재시도 버튼**을 표시한다. |
| **지연** | 로딩 상태를 즉시 표시하고, 9초 후 안내를 강화, **15초 후** "응답이 지연되고 있어요"로 전환한다. |
| **타임아웃** | **30초** 초과 시 `AbortController`로 요청을 취소하고 안내 문구와 재시도 버튼을 표시한다. |

## 4. 예산 플랜 상세 설계

AI 추천 결과의 핵심 파트. 단순 비율 안내가 아니라, 입력한 총예산을 **실제로 어떻게 나눠 쓸지**
감이 오도록 금액 단위로 제시한다.

### 4-1. 분배 항목 (총 5개)

| # | 항목 | 설명 |
| --- | --- | --- |
| 1 | 드레스 | 대여 또는 구매 |
| 2 | 스튜디오 촬영 | 실내 스튜디오 · 야외 스냅 포함 |
| 3 | 메이크업 & 헤어 | 본식 + 촬영 |
| 4 | 부대비용 | 소품 · 부케 · 부모님 한복 등 |
| 5 | 예비비 | 총예산의 8% (돌발 지출 대비) |

각 항목은 **항목명 / 예상 금액(원) / 총예산 대비 비율(%) / 한 줄 코멘트**를 함께 표시한다.

### 4-2. 계산 방식

금액 계산은 **AI가 아니라 서버(Python)** 가 직접 수행한다.
AI에게 금액을 맡기면 합계가 총예산을 초과하거나 계산이 틀릴 수 있기 때문이다.

1. 예비비를 총예산의 **8%** 로 먼저 확정한다 (1만원 단위 반올림).
2. 남은 92%를 4개 항목에 가중치대로 배분한다.
   - 기본 가중치: 드레스 30 / 스튜디오 촬영 28 / 메이크업&헤어 18 / 부대비용 16
   - 사용자가 고른 **1순위 항목에 1.35배** 가중치를 적용한 뒤 정규화한다.
3. 1만원 단위로 내림하고, 남은 잔돈(최대 3만원)은 **1순위 항목이 흡수**한다.

이 방식으로 **5개 항목 금액의 합계는 항상 총예산과 정확히 일치**한다.

> **설계 노트** — 최초에는 잔돈을 예비비에 몰아넣었으나, 총예산이 작을 때(예: 110만원)
> 예비비 비율이 10.91%까지 올라가 기획 범위(5~10%)를 벗어났다. 예비비를 먼저 확정하는
> 방식으로 변경해 전 구간에서 7.69%~8.33%를 유지하도록 수정했다.

### 4-3. 화면 표시

- **가로 막대(바) 차트** — 비율(%)만큼 너비를 채운다. 외부 차트 라이브러리 없이 순수 CSS로 구현.
- **표(테이블)** — 항목 / 예상 금액 / 비율과 합계 행을 함께 제공한다.

### 4-4. 엣지 케이스: 예산 부족

지역·스타일 조합의 최소 권장 예산보다 입력 예산이 낮으면 안내 문구를 함께 표시한다.

| 지역 | 최소 권장 예산 (기준) |
| --- | --- |
| 서울 | 450만원 |
| 부산 | 380만원 |
| 대전 | 300만원 |
| 충청권 | 280만원 |
| 전주 | 280만원 |

여기에 스타일 배수를 곱한다: 럭셔리 ×1.35, 클래식 ×1.10, 모던 시크 ×1.05, 로맨틱 ×1.00, 내추럴 ×0.95.

> 예) 서울 · 럭셔리 → 450 × 1.35 = **607만원**.
> 사용자가 300만원을 입력하면
> *"입력하신 예산(300만원)은 서울 · 럭셔리 조합의 최소 권장 예산(607만원)보다 낮습니다.
> 일부 항목은 조정이 필요할 수 있어요…"* 문구가 결과에 함께 표시된다.

## 5. 지역별 안내 설계

| 지역 | 특징 | 진행 방식 | 권장 예산대 | 예약 리드타임 |
| --- | --- | --- | --- | --- |
| **서울** | 선택지가 가장 많아 비교 기준 수립이 중요. 청담·강남은 프리미엄, 마포·서대문은 합리적 구성 | 드레스 투어 2~3회 + 스튜디오 사전 미팅 | 450만원 이상 | 6~9개월 |
| **대전 · 충청권** | 지역 내 완결형 준비 가능. 둔산·유성 중심으로 제휴사 밀집 | 당일 통합 투어 + 필요 시 서울 촬영 분리 | 300만원 이상 | 4~6개월 |
| **부산** | 해운대·광안리 야외 스냅과의 결합이 강점. 촬영 비중이 상대적으로 높음 | 스튜디오 + 야외 스냅 2부 구성 | 380만원 이상 | 5~8개월 |
| **전주** | 한옥마을 로케이션 활용이 차별점. 한복 촬영 결합으로 부대비용 절감 | 한옥 로케이션 + 스튜디오 혼합 | 280만원 이상 | 4~6개월 |
