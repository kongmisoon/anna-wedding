> 이 문서는 이 프로젝트를 시작할 때 AI 코딩 도구(Claude Code)에 입력한 **최초 프롬프트 원문**입니다.
> 제출용 기록 보관을 위해 수정 없이 그대로 보존합니다.

## 0. 역할 지시 (AI 코딩 도구에게)

당신은 시니어 프론트엔드·풀스택 개발자입니다. 아래 기획을 바탕으로 Anna Wedding이라는 웨딩 토탈 디렉팅 웹 서비스를 처음부터 끝까지 구현해 주세요. 프레임워크(React/Vue 등) 없이 순수 HTML/CSS/JavaScript로 프론트엔드를 만들고, 백엔드는 Vercel Serverless Functions(Python)로 구현합니다. 최종 결과물은 Vercel에 배포 가능한 상태여야 합니다.

작업 중 다음을 지켜주세요.

- 각 파일을 만들 때마다 어떤 역할을 하는 파일인지 주석으로 간단히 설명할 것.
- 에러가 발생하면 임의로 우회하지 말고, 원인을 먼저 설명한 뒤 수정할 것.

- 각 단계(구조 생성 → 프론트 구현 → 반응형 → 백엔드 API → 배포 준비) 완료 시마다 무엇을 했는지 요약해 줄 것.

## 1. 서비스 기획서

### 1-1. 서비스 개요

- **서비스명**: Anna Wedding (애나웨딩)
- **한 줄 정의**: 드레스·스튜디오촬영·메이크업&헤어 세 축을 중심으로, 서울·대전·충청권·부산·전주 지역의 예비 신랑신부에게 맞춤 웨딩 준비를 연결·디렉팅·상담해주는 웨딩 토탈 디렉팅 플랫폼
- **타겟 사용자**: 결혼을 6개월~1년 내 앞두고 있고, 웨딩 준비 정보 탐색에 시간을 쓰기 어려운 20대 후반~30대 예비부부 (특히 지방 거주 또는 지역 이동 결혼 준비 커플)
- **핵심 가치**:
  1. 예산·취향·지역을 입력하면 AI가 맞춤 웨딩 패키지(드레스/스튜디오/메이크업 조합)를 추천해 의사결정 시간을 줄여준다.
  2. 지역별(서울/대전/충청권/부산/전주) 파트너사·진행 방식 정보를 한 곳에서 확인할 수 있다.
  3. 전문 디렉터의 상담을 통해 실제 예약까지 자연스럽게 연결한다.

### 1-2. 페이지/섹션 구성 (SPA 또는 앵커 이동, 최소 5개)

1. **메인(Hero)** — 브랜드 소개, "3대 웨딩 준비를 한 번에" 슬로건, 지역 커버리지 강조, CTA 버튼(AI 추천 받기 / 상담 신청)
2. **서비스 소개** — 드레스 / 스튜디오촬영 / 메이크업&헤어 세 카테고리 각각의 설명, 진행 프로세스, 지역별 제휴 안내
3. **AI 맞춤 웨딩 추천 (핵심 AI 기능)** — 입력 폼 + 결과 카드
4. **지역별 안내** — 서울/대전·충청권/부산/전주 탭 또는 카드로 지역별 특징, 진행 방식, 대표 파트너 유형 소개
5. **상담 문의(Contact)** — 이름/연락처/희망 지역/문의 내용 폼, FAQ 아코디언 포함 가능

- 상단 고정 네비게이션 바로 5개 섹션 앵커 이동, 모바일에서는 햄버거 메뉴로 전환.

### 1-3. AI 기능 설계 — "맞춤 웨딩 패키지 추천"

- **입력값**
  - 예식 지역 (select: 서울 / 대전 / 충청권 / 부산 / 전주)
  - 예산 (숫자 입력 또는 슬라이더, 만원 단위, 드레스+스튜디오+메이크업 합산 예산)
  - 웨딩 스타일 취향 (select 또는 다중 선택: 로맨틱 / 모던 시크 / 클래식 / 내추럴 / 럭셔리)
  - 예식 예정 시기 (월 선택, 예: 2026년 10월)
  - 가장 중요하게 생각하는 항목 (드레스 / 스튜디오촬영 / 메이크업&헤어 중 1순위 선택)
- **출력값**
  - 추천 웨딩 패키지 요약 (드레스 콘셉트 제안 + 스튜디오 촬영 컨셉 제안 + 메이크업&헤어 스타일 제안)
  - 상세 예산 플랜 (아래 "1-4. 예산 플랜 상세 설계" 참고)
  - 해당 지역에서의 진행 팁 및 다음 단계 안내 문구(상담 신청 유도)
  - 결과는 카드 UI로 화면에 표시, "다시 추천받기" / "이 결과로 상담 신청하기" 버튼 제공
- **사용자에게 제공하는 가치**: 웨딩 준비 초기 단계에서 막막함을 줄이고, 예산 안에서 현실적인 방향을 즉시 얻을 수 있음
- **실패 처리 (최소 2가지 이상 구현)**
  1. 빈 입력(필수값 누락) → "지역, 예산, 스타일을 모두 선택해 주세요" 등 구체적 안내 메시지를 입력 폼 근처에 표시하고 API 호출 자체를 막음
  2. API 오류(4xx/5xx) → "추천을 불러오는 중 문제가 발생했어요. 잠시 후 다시 시도해 주세요" 메시지와 재시도 버튼 표시
  3. 지연/타임아웃 → 8~10초 이상 응답이 없으면 "AI가 추천을 준비 중입니다..." 로딩 상태를 보여주고, 15초 초과 시 "응답이 지연되고 있어요. 잠시 후 다시 시도해 주세요" 안내로 전환 (fetch에 timeout 처리 필요, AbortController 사용 권장)

### 1-4. 예산 플랜 상세 설계

AI 추천 결과의 핵심 파트로 예산 플랜을 반드시 포함합니다. 단순 비율 안내가 아니라, 사용자가 입력한 총예산을 실제로 어떻게 나눠 쓸지 감이 오도록 구체적으로 제시합니다.

- **분배 항목 (총 5개, 사용자가 고른 "가장 중요한 항목"에 더 많은 비중 배정)**
  1. 드레스 (대여/구매)
  2. 스튜디오 촬영
  3. 메이크업 & 헤어 (본식 + 촬영 포함)
  4. 부대비용 (소품·부케·부모님 한복 등, 선택적 안내용 항목)
  5. 예비비 (총예산의 5~10%, 돌발 지출 대비)
- **항목별 표시 정보**: 항목명 / 예상 금액(원) / 총예산 대비 비율(%) / 한 줄 설명(해당 지역·스타일 기준 시세 코멘트)
- **총합 검증**: 5개 항목 금액의 합이 사용자가 입력한 총예산을 넘지 않도록 백엔드에서 계산 후 반환 (반올림 오차는 예비비 항목에서 조정)
- **화면 표시 형태**: 표(테이블) 또는 가로 막대(바) 형태로 항목별 비율을 시각화 — 별도 차트 라이브러리 없이 CSS만으로 구현 가능한 단순 바 형태 권장 (예: `<div class="budget-bar" style="width: 32%">`)
- **엣지 케이스**: 총예산이 지역·스타일 조합의 최소 권장 예산보다 현저히 낮을 경우, "입력하신 예산으로는 일부 항목 조정이 필요할 수 있어요"와 같은 현실적 안내 문구를 함께 제공

## 4. 프론트엔드 구현 요구사항

- `index.html`에 5개 섹션을 시맨틱 태그(`<header>`, `<nav>`, `<section>`, `<footer>` 등)로 구성하고, 각 섹션에 `id`를 부여해 네비게이션 앵커로 연결.
- 헤더는 스크롤 시 고정(sticky), 모바일에서는 햄버거 메뉴 토글.
- 디자인 톤앤매너: 로맨틱 파스텔 — 블러쉬 핑크(#F7D9DD 계열), 아이보리(#FFF9F5 계열), 부드러운 골드 포인트(#D8B98C 계열) 조합. 헤드라인은 세리프 계열(예: Playfair Display 등 웹폰트), 본문은 가독성 좋은 산세리프.
- 카드형 UI, 넉넉한 여백, 둥근 모서리(border-radius)로 부드러운 인상 강조.
- AI 추천 섹션은 좌측(또는 상단) 입력 폼 + 우측(또는 하단) 결과 카드 레이아웃. 결과가 없을 때는 "정보를 입력하면 맞춤 추천을 보여드려요" 같은 안내 상태(empty state) 표시.
- 결과 카드 안에는 예산 플랜 테이블/바 차트를 반드시 포함 — 항목명·금액·비율을 한눈에 볼 수 있도록 표시하고, 항목별 바(bar)는 비율(%)만큼 너비를 채우는 형태로 구현(순수 CSS, 라이브러리 불필요).
- 지역별 안내 섹션은 탭 또는 카드 그리드로 구현.
- 모든 폼에 기본적인 클라이언트 측 유효성 검사(빈 값 체크 등) 적용.

## 5. 반응형 요구사항

- 모바일(≤480px), 태블릿(481~1024px), 데스크톱(1025px~) 3단계 브레이크포인트로 CSS 미디어쿼리 작성.
- 네비게이션은 데스크톱에서 가로 메뉴, 모바일에서 햄버거 메뉴 + 슬라이드/드롭다운.
- AI 추천 섹션의 입력 폼과 결과 카드는 모바일에서 세로 스택으로 전환.
- 이미지는 `max-width: 100%` 기본 적용, 지역별 카드 그리드는 모바일에서 1열, 데스크톱에서 다열로 전환.
- 구현 후 최소 두 가지 화면 크기(예: 375px, 1440px)에서 직접 확인하고 스크린샷을 남길 것.

## 6. 백엔드 구현 요구사항 (`api/recommend.py`)

- **엔드포인트**: `POST /api/recommend`
- **요청 바디(JSON)**: `{ region, budget, style, weddingMonth, priority }`
- **처리 로직**:
  1. 필수값 검증 → 누락 시 400과 함께 `{ error: "필수 입력값이 누락되었습니다." }` 반환
  2. 검증 통과 시 AI API(OpenAI 또는 Claude) 호출용 프롬프트를 구성 — 사용자가 입력한 지역/예산/스타일/시기/우선순위를 반영해 "드레스 콘셉트 제안 / 스튜디오 촬영 컨셉 제안 / 메이크업&헤어 스타일 제안 / 항목별 예산 플랜(드레스·스튜디오·메이크업&헤어·부대비용·예비비 5항목의 금액·비율·코멘트) / 진행 팁"을 포함한 구조화된 응답(JSON)을 생성하도록 지시
  3. AI 응답을 파싱해 프론트에서 렌더링하기 쉬운 JSON 형태로 반환. 응답 예시:

     ```json
     {
       "recommendation": {
         "dress": "...",
         "studio": "...",
         "makeup": "..."
       },
       "budgetPlan": [
         { "item": "드레스",       "amount": 2000000, "percent": 40, "comment": "..." },
         { "item": "스튜디오 촬영", "amount": 1500000, "percent": 30, "comment": "..." },
         { "item": "메이크업&헤어", "amount": 800000,  "percent": 16, "comment": "..." },
         { "item": "부대비용",     "amount": 400000,  "percent": 8,  "comment": "..." },
         { "item": "예비비",       "amount": 300000,  "percent": 6,  "comment": "..." }
       ],
       "tip": "..."
     }
     ```

  4. `budgetPlan` 금액 합계가 사용자가 입력한 총예산을 초과하지 않는지 서버 단에서 한 번 더 검증(오차는 예비비에서 보정)하고, 초과 시 비율을 재조정하여 반환
  5. AI API 호출 실패(타임아웃, 4xx/5xx) 시 500과 함께 사용자 친화적 에러 메시지 반환, 서버 로그에는 상세 에러 기록
- 환경 변수에서 API 키를 읽어오며, 키가 설정되지 않은 경우를 대비한 에러 처리 포함.
- CORS는 동일 도메인(Vercel 배포) 기준으로 별도 설정 불필요하나, 로컬 개발 시 필요하면 처리.
- `requirements.txt`에 필요한 패키지(예: `openai` 또는 `anthropic`, `requests` 등) 명시.

## 7. 환경 변수 관리

- **로컬 개발**: 프로젝트 루트에 `.env.local` 생성 후 `OPENAI_API_KEY=sk-...` (또는 `ANTHROPIC_API_KEY=...`) 형태로 저장, `.gitignore`에 반드시 포함.
- **Vercel 배포**: Vercel 대시보드 → Project Settings → Environment Variables에 동일한 키/값 등록 (Production/Preview 모두).
- README.md에 "환경 변수 설정 방법" 섹션을 만들어 키 이름과 발급 경로(예: platform.openai.com, console.anthropic.com)만 안내하고, 실제 키 값은 절대 문서나 스크린샷에 노출하지 않을 것.

## 10. AI 기능 테스트 시나리오 (구현 후 직접 확인용)

- **정상 입력**: "대전 / 예산 500만원 / 로맨틱 / 2026년 11월 / 스튜디오촬영 우선" → 추천 결과 3항목 + 5항목 예산 플랜(금액·비율·코멘트)이 화면에 표시되는지, 5항목 금액 합계가 500만원을 넘지 않는지 확인
- **빈 입력**: 아무것도 입력하지 않고 제출 → "필수 입력값을 확인해 주세요" 안내가 표시되는지 확인
- **오류 유도**: API 키를 임시로 잘못된 값으로 바꿔 호출 → 오류 안내 메시지가 정상 노출되는지 확인
- **지연 상황**: 네트워크를 느리게 시뮬레이션(devtools throttling) → 로딩 상태 및 타임아웃 안내가 정상 동작하는지 확인
